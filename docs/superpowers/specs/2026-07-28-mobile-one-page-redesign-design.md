# 大運動会2026 キャスト向け案内 — 1ページ刷新設計

## 1. 目的

現在の1ページは、390px幅で全長約25,700pxあり、「チーム発表」と「PV音声収録」だけで約11,700pxを占める。情報量を削らず、キャストが参加前に把握すべき内容と、必要になった時に参照する内容を分け、短時間で目的の情報へ到達できるモバイル向け資料へ刷新する。

承認済みの方向性は次のとおり。

- ページは分割せず、1ページのまま段階表示する
- 最重要情報は「イベントの基本ルール」と「チーム編成」
- 集計期間の例外はスケジュール内の注意情報として扱う
- 視覚方向は「運営ドキュメント型」
- 大運動会らしい世界観を維持する
- CSS、JavaScript、画像は `assets/` へ分離する
- GitHub Pagesで配信する

## 2. 情報設計

### 2.1 最初から見せる情報

ヒーロー直後に「まず確認すること」を置き、次の2項目を同格の重要カードとして表示する。

1. イベントの基本ルール
   - 6チーム、各9名のチーム戦
   - 7日間開催
   - 毎日3つのデイリーミッション
   - 獲得ポイントのチーム合計で順位を競う
2. チーム編成
   - 6チームの色と組名
   - 自分の所属チームを選ぶ導線
   - 選択した組のキャスト9名

カードは概要だけで終わらせず、詳細セクションへの明確な操作を付ける。開催期間はヒーロー内に表示するが、集計締切やPV期限と並べた「重要事項一覧」は作らない。

### 2.2 必要な時だけ開く情報

最重要カードの後に、以下を `<details>` を基本とする折りたたみセクションで配置する。

1. 詳しいイベントルール
2. チーム編成
3. スケジュール
4. 優勝・準優勝賞品
5. PV音声収録
6. FAQ・お問い合わせ

各セクションの見出しには、開かなくても内容を判断できる短い補足を付ける。ブラウザのページ内検索で本文を検索できるよう、内容は最初からHTMLに保持する。

## 3. ページ構成 — `index.html`

上から次の順に配置する。

1. 固定ヘッダー
   - BackStageロゴ
   - ハンバーガーボタン
2. コンパクトなイベントヒーロー
   - キャスト向け資料であること
   - 大運動会2026のイベント名
   - 開催期間
3. 「まず確認すること」
   - イベントの基本ルール
   - チーム編成
4. 詳しいイベントルール
5. チーム編成
6. スケジュール
7. 優勝・準優勝賞品
8. PV音声収録
9. FAQ・お問い合わせ
10. フッター

ファーストビューではイベント名と開催期間が見え、その直後に「イベントの基本ルール」が始まる高さにする。

## 4. セクション詳細

### 4.1 詳しいイベントルール

参加から順位決定までの流れに沿って並べる。

1. デイリーミッション3種
2. 各ミッションの目標値と判定条件
3. ポイントのしくみ
4. 重点ミッション
5. 中間発表クイズ
6. 脱落条件
7. 同点時の判定順

基本ルールは重要カードで要約し、数値、計算例、例外条件を詳細側へ置く。目標値と重要条件は詳細セクションを開いた直後に表示し、計算例だけを内側の `<details>` にしてよい。

### 4.2 チーム編成

- 6色のチーム選択ボタンを置く
- 初期状態は「自分のチームを選んでください」と表示する
- 選択した1チームだけ、組名、チーム色、キャスト9名の小さい画像と名前を表示する
- 画像順、キャスト名、チーム分けは現在のページを維持する
- 運営リーダーの割り当ては後日発表という注記を維持する
- 選択状態をURLハッシュへ反映し、同じURLで同じチームを開ける

PV音声収録のチーム別セリフでも同じ選択状態を使用する。一度選択すれば、ページ内で再選択を求めない。

### 4.3 スケジュール

全体日程と各日の集計時間を一つの流れで表示する。例外日は通常日と視覚的に区別し、次を明記する。

- 8月20日: `0:00〜20:00`
- 通常日: 現在の記載を維持
- 最終日: `0:00〜21:00`

これらはページ冒頭の主役にはしないが、スケジュールを開いた時には見落とせない注意枠で表示する。

### 4.4 賞品

「優勝賞品」と「準優勝賞品」を別々のカードで表示し、賞品が2つあることを見出しと配置の両方で明確にする。賞品内容自体は変更しない。

### 4.5 PV音声収録

提出に必要な順で配置する。

1. 任意参加であること
2. 提出期限
3. 収録する5セリフ
   - 全員共通3つ
   - 自分のチーム2つ
4. 選択中チームのキャスト9名の小さい画像
5. セリフごとの指定ファイル名
6. 左揃えで整理した録音方法
7. 提出方法
8. Googleフォーム

チーム別セリフはチーム編成で選択した組を初期表示する。未選択の場合だけ、6チームの選択を表示する。全員共通3つとチーム別2つを視覚的に分け、「5つ」という総数を正しく記載する。

### 4.6 FAQ・お問い合わせ

問い合わせ先はDiscord内の「運営への依頼窓口」とし、チャンネル名とリンクを明記する。既存のFAQ内容を維持する。

## 5. デザイン原則

### 5.1 維持する世界観

- BackStageロゴと大運動会2026のイベントロゴ
- 青空を連想するブルー
- 注意情報に使うオレンジと黄色
- 6組それぞれの現在のチームカラー
- 雲、トラック、ゼッケンなどの運動会モチーフ

モチーフはヒーロー、区切り、チーム識別など用途を限定して使う。本文背景や全カードへの反復は避ける。

### 5.2 読みやすさ

- 本文は原則として左揃え
- 白い本文面と罫線を基本にする
- 大きなグラデーション見出し、丸い見出し、強い影を削減する
- ピル形状はステータス、期限、チーム色など短いラベルに限定する
- 本文は16px以上、行間1.7〜1.8とする
- 補足は13px以上、行間1.6以上とする
- 見出しは青い縦線または小さな番号で階層を示す
- デスクトップでも本文1行を約40〜46字に制限する
- 数値と期限は太字と等幅数字で強調する

## 6. ナビゲーション

固定ヘッダーのハンバーガーメニューから、同じページ内の主要セクションへ移動する。

1. まず確認すること
2. 詳しいイベントルール
3. チーム編成
4. スケジュール
5. 賞品
6. PV音声収録
7. FAQ・お問い合わせ

ページ内リンクは固定ヘッダーに隠れないスクロール余白を持たせる。現在位置に近い項目を `aria-current="location"` で示してよい。Escape、外側タップ、閉じるボタン、フォーカス移動など、現行メニューのアクセシブルな操作を維持する。

```text
│   └── images/
│       ├── brand/

│       └── casts/
│           └── 54名分のJPEG画像

```

公開本体は `index.html` とする。`イベント概要_大運動会2026.html` と `undo-kai.html` は、旧URL互換を維持しながら同じ内容を参照できる構成にする。重複HTMLを残す場合は生成または同期検証を行い、内容のずれを防ぐ。

## 8. 画像とデータ

- 現在のbase64画像からロゴ、ヒーロー、54名のキャスト画像をローカルファイルとして抽出する
- 画像内容、キャスト名、チーム分け、並び順は変更しない
- キャスト画像のファイル名は安定したASCII識別子にする
- チーム編成とPV音声収録は同じ画像ファイルを参照する
- キャスト画像には現在と同じキャスト名の代替テキストを付ける
- 外部画像、外部CSS、外部JavaScriptは使用しない

## 9. JavaScriptの役割

`assets/js/site.js` は次だけを担当する。

- ハンバーガーメニューの開閉
- 画面幅変更時のメニュー自動クローズ
- チーム選択と選択中チームの表示
- チーム編成とPV音声収録の選択状態共有
- URLハッシュと表示状態の同期
- 必要に応じたページ内現在位置の表示

本文や重要情報はHTMLに記載し、JavaScriptだけに保持しない。JavaScriptが動かない場合も、標準の `<details>` を開けば全内容と6チームへ到達できる構造にする。

## 10. 外部リンク

次を維持する。

- PV提出フォーム
- Discord「運営への依頼窓口」

外部リンクは新しいタブで開き、`rel="noopener noreferrer"` を設定する。メールアドレスと件名も現在の内容を維持する。

## 11. レスポンシブ設計

### モバイル

- 基準幅: 390px
- 左右余白: 16px
- 1カラム
- 本文左揃え
- 44px以上の操作領域
- 横スクロールなし
- 初期状態では詳細セクションを閉じ、ページ全体を短く見渡せる

### タブレット

- 基準幅: 768px
- 内容幅を約680pxに制限
- 基本ルールの要約や賞品カードのみ、必要に応じて2カラム

### デスクトップ

- 基準幅: 1280px
- 内容幅を約960pxに制限
- 本文の行長を広げすぎない
- 主要セクションのナビゲーションをヘッダー内にも表示できる

## 12. アクセシビリティ

- 見出し順を `h1` → `h2` → `h3` とする
- メニュー、チーム選択、折りたたみをキーボードで操作可能にする
- フォーカス表示を消さない
- チーム色だけで情報を区別せず、組名を併記する
- 本文と背景のコントラスト比をWCAG AA相当にする
- `prefers-reduced-motion` を尊重する
- スクリーンリーダーで選択中チームと開閉状態が分かるようにする

## 13. テスト

- 1ページ内に全主要セクションとページ内リンクが存在する
- 最重要カードが「イベントの基本ルール」と「チーム編成」である
- 集計時間はスケジュール内に正しく記載される
- 54名のキャスト名、画像、チーム順が維持される
- チーム選択で該当する9名だけを表示できる
- チーム選択がPV音声収録にも反映される
- PV音声5セリフと全ファイル名が維持される
- 目標値、得点、脱落条件、優勝・準優勝賞品が維持される
- 外部リンクのURLと `rel` が正しい
- 旧URLから同じ情報へ到達できる
- JavaScriptなしでも重要情報と6チームすべてへ到達できる
- 390px、768px、1280pxで横スクロールがない
- メニュー、折りたたみ、チーム選択をブラウザで操作できる
- ブラウザのコンソールエラーがない

## 14. 完了条件

- 世界観と運営ドキュメントとしての読みやすさが両立している
- ファーストビュー直後で基本ルールとチーム編成を確認できる
- 集計締切が最重要情報として誤って強調されていない
- モバイルで長文が左揃えになり、中央揃えの説明文がない
- 初期状態ではチーム54名やPV詳細をすべて縦に展開しない
- 既存の内容、数値、54名の画像、PV提出情報を失わない
- GitHub Pagesで1ページ内の全情報へ到達できる
- 自動テストとブラウザ検証がすべて成功する
