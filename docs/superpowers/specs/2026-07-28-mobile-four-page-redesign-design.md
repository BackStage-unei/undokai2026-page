# 大運動会2026 キャスト向け案内 — 4ページ刷新設計

## 1. 目的

現在の1ページ構成は、390px幅で全長約25,700pxあり、「チーム発表」と「PV音声収録」だけで約11,700pxを占める。内容自体は維持しつつ、キャストが必要な情報を短時間で読み取れるモバイル向け資料へ刷新する。

承認済みの方向性は次のとおり。

- 視覚方向は「運営ドキュメント型」
- 大運動会らしい世界観は維持する
- 概要・ルール・チーム・PV音声収録の4ページへ分割する
- CSS、JavaScript、画像は `assets/` へ分離する
- GitHub Pagesで配信する

## 2. デザイン原則

### 2.1 維持する世界観

- BackStageロゴと大運動会2026のイベントロゴ
- 青空を連想するブルー
- 注意情報に使うオレンジと黄色
- 赤・青・黄・緑・橙・紫のチームカラー
- 雲、トラック、ゼッケンなどの運動会モチーフ

モチーフはヒーロー、区切り、チーム識別など用途を限定して使う。本文の背景や各カードへ繰り返し配置しない。

### 2.2 整理する表現

- 本文は原則として左揃え
- 大きなグラデーション見出し、丸い見出し、強い影を削減
- 白い本文面と罫線を基本にする
- ピル形状はステータス、期限、チーム色など短いラベルに限定
- 詳細説明を複数ページへ重複掲載しない
- 開催期間、特殊な集計時間、PV期限だけは概要ページに要約し、詳細ページへリンクする
- 長い説明は「要点→詳細」の順に配置する

### 2.3 基本文字組み

- 本文: 16px以上、行間1.7〜1.8
- 補足: 13px以上、行間1.6以上
- 見出し: 左揃えを基本とし、青い縦線または小さな番号で階層を示す
- 1行の長さ: デスクトップでも約40〜46字を上限とする
- 数値と期限: 太字と等幅数字で強調する

## 3. ページ構成

### 3.1 概要 — `index.html`

最初に確認する情報だけを集める。

1. コンパクトなイベントヒーロー
2. 重要事項
   - 開催期間
   - 8/20の20:00締め
   - 最終日の21:00締め
   - PV音声収録の提出期限
3. イベント概要
4. 主要スケジュール
5. 優勝・準優勝賞品
6. FAQ
7. Discordお問い合わせ

ヒーロー画像は現在より小さくし、ファーストビュー内でイベント名、開催期間、重要事項の先頭まで確認できる高さにする。

### 3.2 ルール — `rules.html`

得点の流れに沿って情報を並べる。

1. デイリーミッション3種の要約
2. 通常日と例外日の集計時間
3. 各ミッションの目標値と判定条件
4. ポイントのしくみ
5. 重点ミッション
6. 中間発表クイズ
7. 脱落条件
8. 同点時の判定順

計算例や詳細な表は `<details>` に入れる。目標値と重要条件は折りたたまず表示する。

### 3.3 チーム — `teams.html`

6チームを色別の `<details>` として表示する。

- ページ上部に6色のチーム索引を置く
- 各チームは組名、チーム色、9名の画像・名前を含む
- 初期表示では全チームを閉じる
- 索引を選ぶと対象チームを開き、その位置へ移動する
- URLのハッシュがチームを示す場合は対象チームを開く
- 画像順とキャスト名は現在のページを維持する
- 運営リーダーの割り当ては後日発表という注記を維持する

JavaScriptが動かない場合も、各 `<details>` を手動で開いて全情報を閲覧できる。

### 3.4 PV音声収録 — `pv.html`

提出に必要な順で配置する。

1. 任意参加であること
2. 提出期限
3. 全員共通の3セリフ
4. チーム選択
5. 選択チームの9名画像と2セリフ
6. セリフごとのファイル名
7. 録音方法
8. 提出方法
9. Googleフォーム

チーム選択は6個のボタンで行い、選択中のチームだけを表示する。初期表示は未選択とし、「自分のチームを選んでください」と表示する。選択状態はURLハッシュに反映し、同じURLを共有すると同じチームを開ける。

JavaScriptが動かない場合は6チームすべてを縦に表示し、情報を失わない。

## 4. 共通ナビゲーション

全ページで同じ固定ヘッダーを使う。

- BackStageロゴ
- 現在のページ名
- ハンバーガーボタン

ハンバーガーメニューには次を表示する。

1. 概要
2. ルール
3. チーム
4. PV音声収録
5. 現在ページ内の主要セクション

現在のページには `aria-current="page"` を設定する。ページ内リンクは固定ヘッダーに隠れないスクロール余白を持つ。Escape、外側タップ、閉じるボタン、フォーカス移動など、現行メニューのアクセシブルな操作を維持する。

各ページ末尾には「次に確認するページ」へのリンクを置き、読み進める順序も示す。

`イベント概要_大運動会2026.html` と `undo-kai.html` は旧URL互換用の案内ページとし、`index.html` へのリンクを表示する。自動転送だけに依存せず、手動で移動できるリンクを必ず置く。

## 6. 画像とデータ

- 現在のbase64画像からロゴ、ヒーロー、54名のキャスト画像をローカルファイルとして抽出する
- 画像内容、キャスト名、チーム分け、並び順は変更しない
- キャスト画像はファイル名を安定したASCII識別子にする
- `teams.html` と `pv.html` は同じ画像ファイルを参照する
- キャスト画像には現在と同じキャスト名の代替テキストを付ける
- 外部画像、外部CSS、外部JavaScriptは使用しない

## 7. JavaScriptの役割

`assets/js/site.js` は次だけを担当する。

- ハンバーガーメニューの開閉
- 画面幅変更時のメニュー自動クローズ
- チーム索引から対象 `<details>` を開く
- PVページのチーム選択
- URLハッシュと表示状態の同期

本文や重要情報はHTMLに記載し、JavaScriptだけに保持しない。JavaScriptエラー時もすべての内容とリンクへ到達できる構造にする。

## 8. 外部リンク

次を維持する。

- PV提出フォーム
- Discord「運営への依頼窓口」

外部リンクは新しいタブで開き、`rel="noopener noreferrer"` を設定する。メールアドレスと件名も現在の内容を維持する。

## 9. レスポンシブ設計

### モバイル

- 基準幅: 390px
- 左右余白: 16px
- 1カラム
- 本文左揃え
- 44px以上の操作領域
- 横スクロールなし

### タブレット

- 基準幅: 768px
- 内容幅を約680pxに制限
- 比較カードのみ必要に応じて2カラム

### デスクトップ

- 基準幅: 1280px
- 内容幅を約960pxに制限
- 本文の行長を広げすぎない
- 4ページのナビゲーションをヘッダー内にも表示できる

## 10. アクセシビリティ

- 見出し順をページごとに `h1` → `h2` → `h3` とする
- メニュー、チーム選択、折りたたみをキーボードで操作可能にする
- フォーカス表示を消さない
- チーム色だけで情報を区別せず、組名を併記する
- 本文と背景のコントラスト比をWCAG AA相当にする
- `prefers-reduced-motion` を尊重する
- スクリーンリーダーで現在ページと選択中チームが分かるようにする

## 11. テスト

自動テストを4ページ構成へ更新する。

- 4ページと共有assetsが存在する
- 全ページの共通ナビゲーションと相互リンクが正しい
- 詳細説明が指定ページに集約され、概要ページの重要事項は要約と詳細リンクだけになっている
- 54名のキャスト名、画像、チーム順が維持される
- PV音声5セリフと全ファイル名が維持される
- 集計時間、目標値、得点、脱落条件、賞品が維持される
- 外部リンクのURLと `rel` が正しい
- 旧URL互換ページから `index.html` へ移動できる
- JavaScriptなしでも重要情報へ到達できる
- 390px、768px、1280pxで横スクロールがない
- メニュー、チーム索引、PVチーム選択をブラウザで操作できる
- ブラウザのコンソールエラーがない

## 12. 完了条件

- 4ページの世界観と文字組みが統一されている
- モバイルで本文が左揃えになり、中央揃えの長文がない
- 390pxで各ページの初期表示高が10,000px未満
- チームページは全チームを閉じた初期状態で2,500px未満
- 概要ページのファーストビューで開催期間と重要事項の先頭が見える

- GitHub Pagesで4ページ間を移動できる
- 自動テストとブラウザ検証がすべて成功する
